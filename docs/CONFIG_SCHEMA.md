# IRIX MCP Server — Configuration Schema

## 1. Overview

Two configuration files govern the server:

| File | Location | Owner | Purpose |
|---|---|---|---|
| `projects.json` | `/etc/mcpserver/projects.json` | Operator-edited | Registry of exposed projects |
| `boundaries.json` | `/etc/mcpserver/boundaries.json` | Generated by `mcpserver apply` | Active enforced policy |

The daemon reads `boundaries.json` at startup (and on `SIGHUP`). It never reads `projects.json` directly — that file is the input to the `apply` step. Backups of both files are written to `/etc/mcpserver/backup/` before each `apply`.

---

## 2. `projects.json` Schema

```json
{
  "version": 1,
  "projects": [
    {
      "name": "my-project",
      "root": "/work/my-project",
      "mcp_access": "read_write",
      "deny_overrides": [".env", ".env.*", "*.secret", "build/"]
    },
    {
      "name": "reference-only",
      "root": "/work/reference",
      "mcp_access": "read_only",
      "deny_overrides": []
    }
  ]
}
```

### 2.1 Top-level fields

| Field | Type | Required | Description |
|---|---|---|---|
| `version` | integer | Yes | Schema version. Must be `1`. |
| `projects` | array | Yes | List of project entries. May be empty. |

### 2.2 Project entry fields

| Field | Type | Required | Description |
|---|---|---|---|
| `name` | string | Yes | Unique identifier. Alphanumeric, hyphens, underscores. Used in `mcpserver show` output and logs. |
| `root` | string | Yes | Absolute path to the project root on the IRIX filesystem. Must be an absolute path. |
| `mcp_access` | string | Yes | `"read_write"` or `"read_only"`. |
| `deny_overrides` | array of strings | Yes (may be empty) | Additional deny patterns relative to this project root. See §2.3. |

### 2.3 `deny_overrides` format

Each entry is a pattern relative to the project root. Supported formats:

- **Bare filename**: `.env` — matches any file or directory named exactly `.env` directly under root
- **Glob with wildcard**: `.env.*` — matches `.env.local`, `.env.prod`, etc.
- **Path prefix**: `build/` — matches the `build` directory and all contents
- **Glob pattern**: `**/.env` — matches `.env` at any depth

Patterns are matched using the portable glob implementation in `src/compat/fnmatch.c`.

**Default deny patterns applied to every project** (not stored in `projects.json`, hardcoded in `generate_boundaries`):
```
.env
.env.*
*.secret
*.key
*.pem
```

## 3. `boundaries.json` Schema

Generated by `mcpserver apply`. Do not edit directly.

```json
{
  "version": 1,
  "generated_from": "/etc/mcpserver/projects.json",
  "generated_at": "2026-05-18T12:00:00",
  "read_write_roots": [
    "/work/my-project"
  ],
  "read_only_roots": [
    "/work/reference"
  ],
  "deny_overrides": [
    "/work/my-project/.env",
    "/work/my-project/.env.*",
    "/work/my-project/*.secret"
  ],
  "write_rules": {
    "allow_create_extensions": [
      ".md", ".txt", ".json",
      ".c", ".h", ".cc", ".cpp",
      ".s", ".S",
      ".sh", ".mk"
    ],
    "allow_create_names": ["Makefile", "Imakefile", "GNUmakefile"],
    "allow_replace_extensions": [
      ".md", ".txt", ".json",
      ".c", ".h", ".cc", ".cpp",
      ".s", ".S",
      ".sh", ".mk"
    ],
    "allow_replace_names": ["Makefile", "Imakefile", "GNUmakefile"],
    "deny_write_globs": [
      "**/.env", "**/.env.*",
      "**/*.secret", "**/*.key", "**/*.pem"
    ]
  },
  "read_rules": {
    "deny_read_globs": [
      "**/.env", "**/.env.*",
      "**/*.secret", "**/*.key", "**/*.pem"
    ]
  },
  "shell_rules": {
    "allowed_commands": ["pwd", "ls", "find", "cat", "grep", "head", "tail", "sed", "wc", "stat"],
    "allow_shell": false,
    "allow_pipes": false,
    "allow_redirects": false,
    "allow_glob_expansion": false
  }
}
```

### 3.1 Top-level fields

| Field | Type | Description |
|---|---|---|
| `version` | integer | Schema version. Must be `1`. |
| `generated_from` | string | Source projects.json path. Informational. |
| `generated_at` | string | ISO-8601 timestamp of last apply. Informational. |
| `read_write_roots` | array of strings | Absolute paths that are fully accessible for read and write (within write_rules). |
| `read_only_roots` | array of strings | Absolute paths accessible for read only. |
| `deny_overrides` | array of strings | Absolute paths or glob patterns that are always denied, regardless of roots. |
| `write_rules` | object | Controls which file extensions and names may be created or replaced. |
| `read_rules` | object | Controls which file patterns are denied for reading. |
| `shell_rules` | object | Controls which commands may be executed via `run_inspect_command`. |

### 3.2 Path authorization precedence

Authorization is evaluated in this order (first match wins):

1. **Deny overrides**: If the path matches any entry in `deny_overrides`, **deny**.
2. **Deny read globs** (for read operations): If path matches any `read_rules.deny_read_globs` entry, **deny**.
3. **Deny write globs** (for write operations): If path matches any `write_rules.deny_write_globs` entry, **deny**.
4. **Root membership**: If the path is under a `read_write_root` or `read_only_root`, **allow** (subject to write rules for write operations).
5. **Default**: **deny**.

## 4. Operator Workflow

```
mcpserver add <name> <root> --rw|--ro [--deny <pattern>...]
mcpserver validate       ← parse projects.json, check paths exist, verify no conflicts
mcpserver show           ← print current registry-derived roots and mounts
mcpserver preview        ← print what boundaries.json would look like after apply
mcpserver apply          ← write new boundaries.json (backup old one first)
mcpserver restart        ← send SIGHUP to daemon to reload policy
```

### 4.1 `mcpserver add` behavior

- Appends a new project entry to `projects.json`.
- Does **not** create the root directory if it does not exist (but warns).
- Default deny patterns (`.env`, `.env.*`, `*.secret`, `*.key`, `*.pem`) are always added.
- Additional `--deny` patterns are appended to the project's `deny_overrides`.
- Does not call `apply` — the operator must do so explicitly.

### 4.2 `mcpserver remove` behavior

- Removes the named project from `projects.json`.
- Does **not** delete any files from the filesystem.
- Does not call `apply` — the operator must do so explicitly.

### 4.3 `mcpserver validate` checks

1. `projects.json` is valid JSON.
2. `version` field is present and equals `1`.
3. All project `name` values are unique.
4. All project `root` values are unique.
5. All `root` values are absolute paths.
6. All `mcp_access` values are `"read_write"` or `"read_only"`.
7. No `deny_overrides` pattern contains `..` (path traversal protection).
8. No `deny_overrides` pattern is an absolute path (must be relative patterns).
9. The generated `boundaries.json` is valid JSON (round-trip check).

## 5. Config File Bootstrapping

On a fresh tardist install, the package places default files at:

- `/etc/mcpserver/projects.json` — empty project list (`{"version":1,"projects":[]}`)
- `/etc/mcpserver/boundaries.json` — empty roots, full shell command allowlist

These defaults are safe: the daemon starts but denies access to all paths until the operator adds at least one project. The standard first-run workflow is:

```sh
# Add one or more projects
mcpserver add myproject /work/myproject --rw

# Preview what the policy will look like
mcpserver preview

# Write boundaries.json and reload the daemon
mcpserver apply

# Enable at boot and start now
mcpserver enable
```

If building from source without using the tardist, create the config directory and defaults manually before starting the daemon:

```sh
mkdir -p /etc/mcpserver/backup
echo '{"version": 1, "projects": []}' > /etc/mcpserver/projects.json
mcpserver add myproject /work/myproject --rw
mcpserver apply
mcpserver enable
```

On upgrades, existing `projects.json` and `boundaries.json` files are preserved
(`config(suggest)` attribute in the tardist IDB). The new default templates are
installed alongside as `projects.json.N` and `boundaries.json.N` for reference.
